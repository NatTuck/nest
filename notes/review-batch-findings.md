## BLOCKER

- `assets/js/hooks/useScrollToBottom.js:68-96` — the rewritten `handleScroll` only re-pins, and un-pinning now happens solely on `wheel`/`touchmove`/`keydown`, so a mouse **scrollbar drag** (and Space/Shift+Space), which emits only `scroll` events, can no longer stop auto-scroll; HEAD handled it via the removed `else if (scrollTop < lastScrollTop) setIsAtBottom(false)`. This regresses the issue being fixed: `notes/issue-06-scroll-up-during-streaming.md:6` lists scrollbar drag as in scope and `:29-32` makes "any scroll event with a smaller `scrollTop` and `distanceFromBottom > epsilon` sets `isAtBottom = false`" an acceptance criterion. The new comment ("a `scroll` event cannot tell a user scroll-up from content growth") is wrong on the growth half — growth changes `scrollHeight`, not `scrollTop`, and the epsilon check runs first — and `useScrollToBottom.test.js:167-178` now pins the regression as intended behavior. Fix: restore a `lastScrollTop` (closure var or ref) and the direction check after the epsilon check; re-point that test at the "content grew while at the bottom" case and add a scrollbar-drag case.
