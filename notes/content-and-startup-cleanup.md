# Combined cleanup: content → parts, agent startup, agents schema rename

Three changes land together because they share file edits and the
schema rename reshapes every place that touches agent identity.

## 0. Glossary (the shapes after this change)

| Term | Shape | Where |
|---|---|---|
| `id` (integer) | `BIGSERIAL PRIMARY KEY` | `agents.id` only. Server-internal. Never sent over the wire. |
| `name` (string) | `VARCHAR NOT NULL UNIQUE` | `agents.name`. The human identifier: URL path, channel topic, PubSub topic, Registry key, frontend. |
| `agent_id` (in `messages`) | `BIGINT FK → agents.id` | DB-internal FK. The `Agent` GenServer does not see this. |

## 3. Persistence — full rewrite

`lib/nest/persistence.ex`. Two renames + a few new functions.

### Rename `upsert_agent/1` → `insert_agent/1`

Takes `attrs.name` (string), lets the DB assign the integer `id`. Returns:

- `{:ok, %PersistedAgent{}}` on success
- `{:error, :duplicate_name}` on Postgres `23505` unique violation
- `{:error, reason}` on other failures

### Add `fetch_agent_by_name/1`

`SELECT * FROM agents WHERE name = $1`. Returns:

- `{:ok, %PersistedAgent{}}` when found
- `{:error, :not_found}` otherwise

### Add `list_agent_names/0`

`SELECT name FROM agents`. Returns a `[String.t()]`. Used by name generation to pre-load DB-resident names into the uniqueness check.

### `load_active_messages/1`

Signature unchanged externally — still takes the agent's `name` (string) and returns `[Message.t()]`. Internally does a JOIN:

```sql
SELECT m.* FROM messages m
JOIN agents a ON a.id = m.agent_id
WHERE a.name = $1 AND m.archived_at IS NULL
ORDER BY m.message_index ASC
```

### `insert_message/2`, `archive_and_compact/4`, `update_next_message_index/2`

- Take the agent's `name` (string) externally.
- Internally resolve to `agents.id` (integer) for the FK insert/update.

Caller signature stays the same; only the internal SQL changes. The `PersistedMessage` row continues to carry `agent_id` as an integer; that integer never escapes the persistence layer.

### `restore_agent/1`

Returns `attrs` with `:name` (string) and `:preloaded_messages`. The integer `id` is resolved internally; callers don't see it.

### `build_agent_attrs/1`

Unifies the fresh-create and restore paths. Always returns:

- `:vocation` loaded (if `:vocation_id` present)
- `:preloaded_messages` — `[]` for fresh, the loaded list for restore
- `:name` from `attrs`

For a fresh create, `build_agent_attrs/1` queries `SELECT * FROM agents WHERE name = $1` once; if not found, returns attrs with `preloaded_messages: []`. For restore, the same query hits; we also load messages and return them. One round trip when the agent exists; one round trip when it doesn't.

## 6. Supervisor — unified `fetch_or_start_agent/1`

`lib/nest/agents/supervisor.ex` — replace `start_agent/1` and `get_agent/1` with one function. No thin wrappers.

```elixir
def fetch_or_start_agent(attrs) do
  attrs =
    attrs
    |> Map.put_new_lazy(:name, fn -> generate_name() end)
    |> Persistence.build_attrs()  # loads vocation, preloaded_messages

  case Persistence.fetch_agent_by_name(attrs.name) do
    {:ok, agent_row} ->
      start_child(attrs, restore: true)

    {:error, :not_found} ->
      try_insert_and_start(attrs, 5)
  end
end

defp try_insert_and_start(attrs, attempts) do
  case Persistence.insert_agent(attrs) do
    {:ok, _agent_row} ->
      start_child(attrs, restore: false)

    {:error, :duplicate_name} when attempts > 0 ->
      new_attrs = %{attrs | name: generate_name()}
      try_insert_and_start(new_attrs, attempts - 1)

    {:error, :duplicate_name} ->
      {:error, :could_not_generate_unique_name}

    {:error, reason} ->
      {:error, reason}
  end
end

defp generate_name do
  existing =
    (Registry.list() ++ Persistence.list_agent_names())
    |> MapSet.new()

  NameGenerator.generate_unique(existing)
end
```

Behavior:

- **Single function** — replaces `start_agent/1` and `get_agent/1` entirely.
- DB is the source of truth for "does this agent exist?"; the in-process `Registry` is a pure cache for "is this running in this BEAM?".
- **Regen-and-retry** on `Persistence.insert_agent/1` returning `:duplicate_name`. Five attempts is generous; the MapSet-based fast-path in `generate_name/0` covers the common case; the DB unique constraint is the ultimate arbiter.
- `Registry.lookup` is no longer used to detect existence — only to resolve pids for already-running agents when callers ask.

`NameGenerator.generate_unique/1` (already takes a `MapSet` of existing names) gets the combined in-process + DB-resident names. This reduces collision probability; the DB unique constraint handles the rare race.

## 7. System message persistence

Lands in this same change. After `start_child` succeeds for a fresh-create, when persistence is enabled, insert the system message built by `Init.build_state/2`:

```elixir
defp maybe_persist_initial_system_message(name, state) do
  if persistence_enabled?() do
    agent_row = Persistence.fetch_agent_by_name!(name)
    [system_msg | _] = state.chat_state.messages
    Persistence.insert_message(agent_row.id, system_msg)
  end
end
```

`seed_preloaded_messages/2` keeps its defensive prepend for pre-existing rows that have messages but no persisted system message:

```elixir
defp seed_preloaded_messages(state, preloaded) do
  if Enum.any?(preloaded, &match?({:system, _}, &1)) do
    do_seed(state, preloaded)
  else
    [system | _] = state.chat_state.messages
    shifted = Enum.map(preloaded, fn {role, %{index: idx} = msg} ->
      {role, %{msg | index: idx + 1}}
    end)
    do_seed(state, [system | shifted])
  end
end
```

This makes the system prompt survive BEAM restart.

## 8. Content → parts cleanup

`content` is fully redundant across the client:
- Finalized message `content` (set by `addUserMessage` optimistic add and by the streaming→message merge).
- Streaming accumulator `content` (kept in sync with `segments` by hand).
- Partial accumulator `content` (same).

`parts` is the canonical shape on the wire. `segments` is a parts list under a different name in the streaming accumulator. Eliminate `content` everywhere; consolidate on `parts`.

### 8.1 New shared util

`assets/js/utils/messageText.js`:

```js
export function textFromParts(parts) { ... }

export function messageText(message) {
  if (!message) return "";
  if (Array.isArray(message.parts)) {
    const fromParts = textFromParts(message.parts);
    if (fromParts) return fromParts;
  }
  return typeof message.content === "string" ? message.content : "";
}

export function streamingText(streaming) {
  if (!streaming) return "";
  if (Array.isArray(streaming.parts)) {
    const fromParts = textFromParts(streaming.parts);
    if (fromParts) return fromParts;
  }
  return typeof streaming.content === "string" ? streaming.content : "";
}
```

The two flavors make the partition explicit: renderers reading from `cache.messages[i]` go through `messageText`; renderers reading from `cache.streaming` / `cache.partial` go through `streamingText`.

### 8.2 `accumulateSegment` → `accumulatePart`

`assets/js/store/index.js:65-95`. Output `[{kind: "text"|"thinking", text|thinking}, ...]`. Rename `currentType` → `currentKind`. Same branching (same kind → extend last part; different → new part).

### 8.3 Streaming accumulator stores `parts`, not `segments` + `content`

`assets/js/store/index.js:454-646`. Drop `streaming.content` and `partial.content`. Drop the "thinking updates segments but not content" rule at lines 514-517 and 617-620.

Both branches of `addChatDelta` produce a `parts` list via `accumulatePart`. The legacy `charsStart`/`charsEnd` overlap math and integrity check at lines 562-595 substitute `streamingText(partial)` for `partial.content`. `charsReceived` stays (byte count, not a content field).

### 8.4 `addUserMessage` writes `parts` only

`assets/js/store/index.js:908-956`. Replace `content: content` with `parts: [{kind: "text", text: content}]`. Optimistic message shape now matches a server-broadcast message from frame 1.

### 8.5 `addChatMessage` merge simplifies

`assets/js/store/index.js:829-887`. The two `content: flatten(message) || m.content || ""` lines (862, 877) collapse to `parts: <from broadcast> || m.parts || []`. No more mixed-shape merging.

### 8.6 Renderers read `parts` (or derived text) only

- `assets/js/pages/ChatPage.jsx:603-646` — `SystemMessageContent({ parts, isPartial })`. Uses `messageText({ parts })`. Placeholder fires only when both `parts` and legacy `content` yield nothing.

## 9. Context probing → Models cache

The per-agent async probe that fires after `Agent.init/1` is gone. The `/v1/models` fetch happens once per provider on application startup (already happens in `Nest.Models`), and the per-model context limit is cached.

### 9.1 `Nest.Models` — new cache

```elixir
%{
  static_config: config,
  models: %{name => %Model{}},             # existing
  context_limits: %{provider => %{model_id => {source, limit}}}  # new
}
```

On `:query_auto_providers` (and on `refresh/0`), for each auto-provider: fetch `/v1/models` ONCE per provider. From the response, build:
- The model-ID list (existing `extract_all_models/2`).
- The per-model context limit using `ProviderShapes.extract_limit_from_model/1`.

Both keyed by provider name.

For static providers (no `auto-models`), the context limit comes from DotConfig (`[models] context-limit = ...`).

### 9.2 Public API

```elixir
@spec context_limit(provider :: String.t(), model :: String.t()) ::
        {source() | nil, pos_integer() | nil}
def context_limit(provider_name, model_id)
```

Returns `nil` if unknown. Cached forever (until `:refresh`).

### 9.3 `Agent.Config.configured_context_limit/1` precedence

1. DotConfig `models.<name>.context-limit` → `:config`
2. Cached `Models.context_limit(provider, model)` → the discovered source (`:vllm` / `:openrouter` / `:llama_cpp`)
3. `nil`

`Init.initial_context_limit/1` becomes purely synchronous. No `:default` placeholder, no async probe, no caveat rendering.

### 9.4 Drop the per-agent probe

- `lib/nest/agents/agent.ex`: drop `__spawn_context_limit_probe__/2`. Drop `run_post_init/2`. Move the startup `Logger.info` into `init/1` directly.
- `lib/nest/agents/agent/handlers.ex`: drop `route_for({:discovered_context_limit, _, _})` and `discovered_context_limit/3`.
- `lib/nest/agents/agent/system_prompt.ex`: drop the `:default` caveat branch in `context_limit_section/1`.

### 9.5 `Nest.LLM.ProviderShapes` (renamed from `Nest.LLM.Discover`)

`Discover.context_limit/1` and `Discover.fetch_models/1` become unused (they're called from the per-agent probe, which is gone). Delete those two functions. Rename `Discover` to `Nest.LLM.ProviderShapes`. Keep `extract_limit_from_model/1` as the only public export — both `Nest.Models` and any future per-agent caller can use it.
